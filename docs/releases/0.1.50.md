# Dynsight 0.1.50 — Callback tables and diagnosis

Explicit member initialization such as `.pre = prepare` now remains attached to
its object even when its structure definition is outside the index. Pointer and
return types retain their layers through forward declarations, allowing getter
returns, registration arguments and stored pointers to connect to actual callback
candidates in Callers, Callees and Callers & Callees.

Argument matching uses each function's parameters; no argument position is
hardcoded. Tests cover the first through fourth positions with and without the
structure definition. Positional field initializers still require a known layout.

When no callback is resolved, **Callback analysis** opens automatically with
recorded reasons: missing getter bodies, missing argument supplies, unavailable
object/member values or unavailable structure layouts. These are analysis
limitations, not proof of a runtime error.

Macro/callback limits now show **Partial index: analysis limits reached**.
Existing relations remain usable. Memory and inference budgets are unchanged.
Help and README document the diagnostics.

Install the VSIX for Windows, macOS or WSL. After updating, use **Rebuild index**,
then select the enclosing caller in **Callers & Callees**, or click the callback
member at its call site to inspect candidates and diagnosis.

The reported firmware connection was reconstructed in tests. The complete
private WSL project has not been executed locally; other missing-source or
analysis-limit causes may still leave callbacks unresolved.
