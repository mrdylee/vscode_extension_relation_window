# Dynsight 0.1.59 — WSL

With **Analyze Callbacks** enabled, unrelated opaque calls can fill the
256-entry ordered region summary. This release preserves that warning while
keeping independent callback targets complete, without an extra unresolved edge.
The getter -> init argument -> saved global pointer -> callback chain is covered
by regression tests at 256, 257 and 270 separately addressed scalar fields.

Omitted regions are retained as bounded uncertainty and propagated through
function summaries. A no-argument helper that may change a global callback
still leaves that callback unresolved. If reachable-object traversal itself is
truncated, or the bounded omission record fills, project-wide uncertainty remains.
The existing limits are unchanged. Parent/child region reduction and scalar
summary optimization are outside this release.

Validated with generated C inputs, safety regressions, Worker transfer, browser
UI and Extension Host checks. The user's complete WSL source project is not
available here; this release does not establish that every reported WSL warning
or callback has been resolved.

Install `dynsight-0.1.59-wsl.vsix` into VS Code's WSL extension host, reload the
window and rebuild the index with **Analyze Callbacks** enabled. Copilot is not
required. The common and legacy VSIX filenames remain available for updater
compatibility.
