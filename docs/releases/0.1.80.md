# Dynsight 0.1.80 — Restore AI callback fallback with selected builds

Fixes a regression where selecting a Build configuration could remove previously
available AI callback links from basic-navigation files. The View used the basic
source index for those files while AI read and projected only the Build index.

- Include fallback source call sites in AI analysis and publish validated candidates
  into the same index used by navigation, even with an empty/partial Build result.
- Keep basic and contextual evidence searches separate and avoid duplicate raw
  call sites for files with a Build context. Preserve static function identities.
- Restore valid AI cache results and manual target actions for fallback sites.

Install the matching Windows/macOS/WSL VSIX and reload the window. Keep the Build
selection and run **Dynsight: Analyze Callbacks with Copilot** if analysis was
previously stopped. Existing model settings, scope, candidate/evidence validation,
request/work/memory limits and analysis cache version14 are unchanged.

The reported WSL workspace and live model response were not accessible here;
validation uses synthetic callbacks, a mocked AI provider and cross-platform
runtime checks. AI candidates retain their uncertainty labels.
