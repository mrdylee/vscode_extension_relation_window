# Dynsight 0.1.51 — Separate callback analysis option

**Settings → Analyze Callbacks** is enabled by default. It controls inferred
function-pointer/structure callback targets and callback selection in Callers,
Callees and Callers & Callees. Turn it off to skip callback propagation and use
ordinary symbol navigation. **Include Function Arguments** remains independent:
literal function names/addresses can still appear with callback analysis off;
alias-derived argument targets require callback analysis.

Changing the option recalculates relationships from existing source facts without
reparsing files. Any current analysis finishes first. It does not immediately
cancel an analysis or recover files that failed earlier. Basic parsing and macro
expansion retain their memory use and safety limits. Reports include the setting.

Fix a reproduced navigation bug: when another expression in a function expanded
a macro, ordinary callback calls could retain only the receiver's source range.
The full callee range is now preserved so clicking the member opens candidates.
The private WSL project's remaining target-resolution limits are not confirmed
resolved; inspect **Callback analysis** and **Analysis notices** if needed.

Pre-change recovery tag: `checkpoint/pre-callback-settings-20261020`.
Install the VSIX for Windows, macOS or WSL, reload, and use **Settings → Analyze
Callbacks** to compare behavior. README and the bundled Help explain both options.
