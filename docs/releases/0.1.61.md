# Dynsight 0.1.61 — WSL

A callback skipped when full analysis stopped could show zero candidates with
no Callback analysis details. Unobserved indirect calls now retain a clear
not-evaluated reason and the original project-budget notices.

After a time/work stop, a bounded registration projection can retain short
getter -> argument -> saved pointer -> callback paths as **Registered candidates**.
These candidates are always incomplete, with source evidence and an explanation
that other bodies/mutations may have been omitted. The original unresolved call,
Partial index status and notices remain. Candidates are not proven invocations.

Full analysis still uses its existing 10-second, work and storage limits. The
registration projection checks a separate 250 ms cooperative deadline, inspects
at most 32768 syntax containers and excludes bodies/initializers over 512
containers. It is best effort, skips memory-limit runs and stops under memory
pressure. It does not guarantee a candidate for every large project or eliminate
whole-project analysis limits. Analyze Callbacks remains enabled; Copilot is
not required. Complete analysis results and the disabled setting are unchanged.

Install `dynsight-0.1.61-wsl.vsix` into the WSL extension host, reload VS Code and
rebuild the index. For a partial result, select the callback and inspect its
Registered candidate plus Callback analysis reasons. The photo-derived reduced
case is validated locally; the full user WSL project remains unverified.
