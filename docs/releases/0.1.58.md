# Dynsight 0.1.58

## Callback registrations without calls

Assignments such as `fp = handler`, `fp = &handler`, `ops.cb = handler` and
`.cb = handler` now appear as **Registration** relationships in Callers/Callees
even without a later invocation. Global initializers belong to the initialized
variable; local initializers and assignments belong to the enclosing function.
Click a registration to preview its source location. Registration does not prove
execution and remains distinct from **Registered candidate** call sites.

With **Analyze Callbacks** off, simple function-pointer and local structure-member
assignments still supply call candidates, including `p->cb = handler; p->cb();`
through a structure pointer parameter. Unknown writes and address escapes clear
affected candidates. RHS calls such as `fp = factory()` are not literal function
registrations. Inactive and unevaluated assignments remain excluded.

Analysis caches from earlier versions are rebuilt. Existing callback analysis
limits remain; this release does not guarantee resolution of every callback.

## Copilot waiting and resumption

Show the current reason and next action when Copilot is waiting for saved sources,
indexing or Worker recovery. Explicit Analyze/Reanalyze requests resume once the
saved index is ready. Startup and navigation still reuse cached results only.

The 0.1.57 CI gate caught an outdated integration-test expectation; no 0.1.57
release was published. This release updates that assertion and verifies that
registrations remain distinct from actual calls.
