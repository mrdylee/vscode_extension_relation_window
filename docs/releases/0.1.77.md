# Dynsight 0.1.77 — Make build configurations and contextual analysis

## Downloads

Choose `dynsight-0.1.77-windows.vsix`, `dynsight-0.1.77-macos.vsix` or
`dynsight-0.1.77-wsl.vsix`. In the matching VS Code environment, run
**Extensions: Install from VSIX…**, select the file, then reload when requested.
For WSL, install in the WSL extension host. All platform filenames contain the
same universal JS/WASM extension. Universal and legacy updater aliases and
`SHA256SUMS.txt` are also provided.

## Make build configurations

- Run **Dynsight: Select Build Configuration**, or use **Build** in the footer,
  to select an existing Makefile or build script. Dynsight searches from indexed
  source directories toward the workspace root and follows the chosen script's
  Make includes and sub-make calls, including multiple modules and nested `.mk`
  files. An entry missed by discovery can be selected manually.
- Supported file-specific defines, undefines, include paths and forced inputs
  help resolve inactive branches before macro/callback propagation. The preview
  shows commands, working directories, source locations and unresolved inputs.
  Neither Make, scripts nor a compiler are executed. `compile_commands.json`
  is not required.
- Keep different translation units' shared-header environments separate while
  preserving original source locations. Relation, Context and the existing AI
  callback feature use the selected context and configuration fingerprint.
- Ordinary source edits reuse build metadata; configuration dependencies trigger
  refresh. Cached facts and Worker results are checked against the current
  source/configuration generation. **Refresh Build Configuration** forces a
  metadata recheck. General Include/Exclude and Smart Analysis scopes still apply.

## Other improvements and cache compatibility

- Include the analysis folder pickers, firmware output/test exclusions,
  callback registration and precision fixes, and compact progress footer
  developed since 0.1.76. Saved explicit scopes are preserved.
- Analysis cache compatibility is now **13**. Rebuild incompatible saved analysis
  when prompted. User-confirmed targets stay stored separately; changed source
  or build configuration can require review.
- Existing macro, callback, mutation, variant, cancellation and memory protections
  remain active. No analysis limit was raised to obtain the new results.

## Limits and verification

This is a bounded static subset of sh/cmd/Make and GCC options. Dynamic expressions,
unsupported options, excluded/missing headers and compiler defaults can leave the
result partial. Diab-specific option semantics and final link/source membership
are unverified. Cross-translation-unit links retain explicit uncertainty.
`skipInactive=false` keeps all-branch source analysis. MCP/T32 integration and a
build runner are not included.

Local regression tests include configuration-driven callback target changes in
the real VS Code Extension Host. Synthetic fixtures are not confirmation of the
team's private GCC/Diab firmware, Windows/WSL installation or live Copilot service.
Detailed analysis of large projects can still be slow or partial.

Implementation evidence and remaining limits are in
`docs/reviews/2026-10-25-build-context-validation.md`. Release gates, packaged
runtime and public-download checks are recorded in
`docs/reviews/2026-10-25-release-0.1.77.md`.
