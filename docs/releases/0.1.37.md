# C Relation Explorer 0.1.37

- Fix a reproduced navigation memory spike when Callees resolves many same-name
  functions across board/SDK variants. Candidate information used internally by
  the resolver is no longer duplicated into every displayed call site.
- Keep all displayed call locations, ambiguity indicators, function-argument
  relationships, previews and source navigation. The existing 300-node limit and
  complete internal resolution results are preserved.
- Verify the fix with an actual 128-MB-heap failure reproduction, 100 repeated
  graph builds and 40 native VS Code selections using the packaged extension.

This addresses a confirmed graph-generation/transport allocation problem.
It does not establish that every reported WSL stop has that same cause or remove
the analysis Worker's separate memory budget. If Relation still stops, record the
first **Analysis notices** error and the status shown at the bottom.

Windows, macOS and WSL downloads contain the same universal VSIX. Install in the
WSL extension host when using WSL. After updating, use **Developer: Reload Window**
and confirm **C Relations v0.1.37**. **C Relations: Check for Updates** checks
immediately rather than waiting for the normal daily check.
