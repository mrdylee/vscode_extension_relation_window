# Dynsight 0.1.82 — Conditional callback propagation fixes

C callback analysis now preserves the original and assigned targets when a
logical expression conditionally writes a callback or calls a setter. Nested
ternary expressions retain their separate side effects. For example,
`flag && (cb = second)` keeps both `first` and `second` when `cb` starts at
`first` and the flag is unknown.

Review also corrected unnecessary propagation branches for logical expressions
without side effects. Large collections of ordinary boolean conditions no
longer consume this extra work before a later callback call.

GCC and Diab build context refresh, source edits and disk cache restoration are
covered by regression tests. Analysis cache compatibility advances to 16, so
existing saved analysis rebuilds after the update.

Install the matching Windows/macOS/WSL VSIX and reload VS Code. Existing callback
and memory limits remain in force. Public FreeRTOS profiling still reproduces
long analysis; the reported private-firmware limit warnings and overall latency
are not claimed resolved by this release.
