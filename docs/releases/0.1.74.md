# Dynsight 0.1.74 — Automatic Copilot callbacks and a compact footer

## WSL download

Install `dynsight-0.1.74-wsl.vsix` in the WSL extension host. In a VS Code window
connected to WSL, run **Extensions: Install from VSIX…**, select the file, and
reload when requested. Verify Dynsight 0.1.74 appears under **Installed in WSL**.
Native Windows, macOS and updater aliases contain the same universal JS/WASM
package. Checksums are supplied in `SHA256SUMS.txt`.

## Changes

- Basic navigation, Local and Copilot status share one footer row at narrow and
  wide panel sizes. Long text uses ellipsis. Stop local remains fixed as function
  names and elapsed time change; hover and Copy still expose the full name.
- **Choose callback…** is removed. When **Copilot Callbacks** is enabled, eligible
  unresolved callbacks are analyzed automatically once the saved index is ready.
  Requests run one at a time, continue beyond five calls, and reuse valid cache.
- This changes 0.1.72/0.1.73's manual-only policy. Enabling the setting, startup,
  saved source changes, Rebuild and model/scope changes may send relevant source
  to the selected Copilot model. Existing Copilot Include, Copilot Exclude and
  Detailed Analysis Folders still apply. Empty Copilot Include permits no requests.
- **Stop analysis** pauses automatic requests for this session and retains
  completed results. Errors pause without automatic retries or model fallback.
  Resume with **Analyze Callbacks with Copilot**, toggle Copilot Callbacks, or
  change its model/scope. Active **User confirmed** calls are skipped; individual
  **Recheck with AI** comparisons remain available.
- Source/model changes invalidate stale replies. Individual rechecks no longer
  inflate completed progress. User-confirmed targets remain stored separately.

Analysis cache compatibility remains **6**. Actual WSL installation and live
Copilot responses are separate from the automated package/CI checks; no new
claim of firmware or model accuracy is made.
