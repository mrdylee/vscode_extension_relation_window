# Dynsight 0.1.53 — Bound callback mutation analysis

Reduce false **Partial index** warnings caused by ordinary scalar writes.
Proven unread scalar declarations no longer consume the callback effect budget.
Array selectors, address uses, fields read through compatible declarations in
other files, and unresolved storage remain conservative.

Opaque calls now mark bounded storage regions instead of generating an unknown
effect for every field. Follow nested pointees and helper parameters, preserve
conditional paths, and allow later exact assignments to restore that slot.
Objects supplied at different call sites remain separate.

An unrelated function's mutation limit no longer marks every callback incomplete.
Omitted effects still invalidate dependent storage, including globals changed
by functions with no arguments. Project-wide limits retain incomplete results.
The existing 256 explicit effects, 10-second callback budget and memory guard
remain; region tracking is also bounded. This does not guarantee a complete
index or faster indexing for every project.

Regression tests include the array registration → lane → group → local callback
copy pattern, both outgoing and incoming calls, scalar selectors, opaque
mutations, cross-file structure declarations and real limit cases.

Install the VSIX, reload VS Code, and run **Rebuild index** once.
If a callback is still unresolved, **Diagnostics → Report issue** can capture the
new result. The private WSL firmware has not been rerun in this environment.
