# Dynsight 0.1.52 — Locate callback analysis limits

**Analysis notices** now puts callback/macro limits before syntax notices.
Callback details identify the actual observed file, line and function, plus
analysis stage, project/scope elapsed time and expression evaluation counts.
At most 64 detailed records are retained per inference run.

The callback time budget is project-wide. **Project budget observed at** marks
the place where the check stopped analysis, not a claim that one function used
the whole budget. Scope counters cover the current function visit or initializer.
**Report issue** includes categories and numeric counters without source names,
paths or raw diagnostic messages.

Remove unused function mutation summaries from global initialization. Large
static arrays no longer falsely hit the 256-slot function mutation limit.
Global heap writes and callback targets remain intact. Real function mutation,
10-second inference, memory and macro limits are unchanged.

Install the VSIX, reload, and run **Rebuild index** once to capture new diagnostics.
If a callback remains unresolved, expand **Analysis notices** and share a photo
or reviewed report. This release does not claim that every private WSL callback
failure or time-budget limit is resolved.
