# Dynsight 0.1.56 — Callback candidates and Copilot model-switch fixes

## 콜백 함수 탐색

- 정적 **Analyze Callbacks**를 꺼도 `.cb_process = target` 등록과
  `p = &table; p->cb_process()` 같은 단순한 지역 포인터 연결을
  **Registered candidate**로 표시합니다. 등록·연결 근거로 이동할 수 있습니다.
- 같은 객체와 멤버를 확인하며, 단순 별칭은 최대 16단계까지만 따라갑니다.
  분기·반복문·getter·함수 간 전달은 이 기본 탐색의 지원 범위가 아닙니다.
  후보는 실제 실행의 증명이 아니며 기존 미해결 호출식도 유지합니다.
- 정적 분석이 꺼져 있어도 등록 후보와 AI 후보를 호출부에서 선택할 수 있습니다.
  타입으로 확인되는 일반 함수 포인터 `cb()`도 Copilot 분석 대상에 포함합니다.

## Copilot 상태와 멈춤 개선

- 하단에 처리/감지된 전체 호출부, 남은 수, 실패, 후보 없음, 문맥 제한을 표시합니다.
  **Analyze next 5**로 다음 최대 5건의 새 분석 요청을 실행할 수 있습니다.
- **Index ready**는 로컬 색인 상태입니다. **All detected sites processed**는
  감지한 호출부 처리가 끝났다는 뜻이며, 모든 실행 대상을 찾았다는 뜻은 아닙니다.
- 이전 모델이 취소에 응답하지 않아도 모델 변경이 완료되도록 수정했습니다.
  모델 조회·토큰 계산·요청·응답 스트림에 취소와 60초 제한을 적용하며,
  뒤늦게 도착한 이전 결과는 새 모델의 상태에 반영하지 않습니다.
- 저장된 AI 후보를 복원할 때 같은 파일의 참조를 반복 탐색하던 병목을 줄였습니다.
  로컬 테스트의 80,000개 참조 / 1,000개 후보 적용은 약 1,019ms에서 37ms로
  감소했습니다. 실제 프로젝트 성능은 코드 구성과 장치에 따라 달라집니다.

## 업데이트 후 사용

1. 해당 플랫폼의 VSIX를 설치하고 VS Code 창을 다시 로드합니다.
2. **Dynsight: Rebuild Index**로 버전이 바뀐 로컬 캐시를 다시 만듭니다.
3. AI 분석을 원하면 명령 팔레트에서
   **Dynsight: Analyze Callbacks with Copilot**을 실행합니다.
   모델 선택·옵션 활성화만으로는 새 AI 요청을 시작하지 않습니다.
4. 남은 항목은 **Analyze next 5**로 이어서 처리합니다. 후보를 찾으면 기존
   `object->callback` 호출식과 별도로 **AI candidate** 함수가 추가됩니다.

기존 매크로·정적 콜백 분석의 제한값은 유지합니다. 사용자 Windows 프로젝트와
실제 Copilot 계정 응답을 이 환경에서 실행한 것은 아닙니다. 로컬 회귀 테스트는
등록 탐색, 진행률, 모델 전환, 취소·시간초과와 대량 후보 적용을 검증합니다.

Windows/macOS/WSL VSIX는 동일한 공용 확장 패키지이며 파일 이름으로만 구분합니다.
WSL에서는 해당 원격 VS Code 창에 설치하세요. Marketplace 게시가 아닌 GitHub
Release 배포입니다.

0.1.55는 새 테스트의 빌드 경로 의존 문제로 CI에서 중단되어 공개되지 않았습니다.
0.1.56은 해당 테스트 설정을 수정하여 위 변경 사항을 배포하는 버전입니다.
