# Dynsight 0.1.62 — WSL callback limit diagnostics

This release makes the remaining Partial index problem diagnosable on an offline
or security-isolated PC. It does not remove the 256-entry or 10-second limits.

Expand **Analysis notices** to see:

- The overflow operation, retained count, first omitted storage location and up
  to eight retained examples. Mutation slots represent distinct storage effects,
  not files or callback functions. Region limits are separate.
- Up to eight functions ranked by cumulative propagation expression evaluations,
  with actual analysis runs, cache hits and accumulated elapsed time. A project
  deadline's observed location is not necessarily its most expensive function.

The cost list excludes setup/global initialization and is not a CPU profile.
Storage samples describe the first recorded overflow, not all omitted writes.
Names and storage samples remain local; the Report issue projection excludes
these fields. No source upload or new network operation is introduced.

Install `dynsight-0.1.62-wsl.vsix` in the WSL extension host, reload VS Code, keep
**Analyze Callbacks** enabled and run **Dynsight: Rebuild Index**. Inspect the
expanded notices locally. The actual 196-file security-PC corpus is unavailable
for remote verification; synthetic reproduction is not proof that it is fixed.
