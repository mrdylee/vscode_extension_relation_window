# Dynsight 0.1.68 — Callback type and memory-model fixes

This release addresses the analysis.md findings that were not included in 0.1.67.

## Types and callback storage

- Collect typedef names that Tree-sitter represents as primitive declarators.
  Resolve visible definitions first; recognize standard integer/size types when
  their definitions are outside the index.
- Preserve normalized base types and selector dependencies when indexing arrays
  or dereferencing pointers. Unrelated integer fields, byte writes and scalar
  array initialization no longer consume callback mutation/region slots.
- Keep actual callback fields, pointer aliases, relevant numeric selectors and
  genuine analysis-limit uncertainty tracked. The 256-slot and 10-second bounds
  are unchanged.

## Memory operations and caching

- Model external `memcpy`, `memmove` and `memset` as writes to destination storage.
  Source objects and the objects referenced by destination pointer fields are
  preserved, including through helper function summaries.
- Preserve zero-length operations and the destination return alias. Byte ranges
  may cover the containing destination array; copied or zero-filled callback
  bytes remain uncertain. Indexed user definitions use their own call effects.
- Keep `sizeof`/alignment operands unevaluated while retaining unknown results
  instead of incorrectly treating every size as zero.
- Re-evaluate cached functions when the storage they depend on changes, rather
  than when unrelated heap entries or invalidation regions change. Matching
  invalidations, new array entries and wildcard writes still refresh readers.

## Rebuild required

Analysis compatibility advances from 1 to 2 because parsed and inferred results
have changed. Run **Rebuild Index** once after upgrading. This is a compatibility
change, not an index-damage condition. Ordinary compatible updates still reuse
the local cache. Rebuild alone does not start paid AI requests.
