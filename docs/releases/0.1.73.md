# Dynsight 0.1.73 — Basic callback facts before detailed analysis

Includes the scoped settings, manual Copilot investigation, user-confirmed
callback targets, fixed Stop position and function-name Copy from 0.1.72.

## Basic facts first

Explicit registrations and literal function arguments now appear before detailed
macro expansion or callback propagation begins. Basic navigation no longer waits
for the detailed pass to finish before exposing these facts.

- Stop during basic registration collection keeps its valid prefix. Stop during
  later detailed work preserves every already-published basic fact as well as
  any detailed candidates found so far. Retry reuses the parsed source input.
- Late basic-result messages are checked against the active request, source
  versions and policy key, keeping older generations out of the current view.
- Warm passes preserve existing full relationships; basic snapshots are reused
  for unchanged sources and invalidated when source data is removed or replaced.
- Completed basic timing is cleared before detailed work starts. Registration
  cancellation retains the correct stage and bounded diagnostics.

Unversioned legacy cache roots remain recognized. A 0.1.72 workspace using the new
default basic scope is not silently switched to legacy full analysis on upgrade.

Analysis compatibility is **6**. Run **Rebuild index** for an incompatible saved
snapshot. User-confirmed choices are separate from that cache and remain stored.
Copy accepts Unicode function-name snapshots, and names above the clipboard
message limit receive failure feedback with the selectable-text fallback.
Whole-project detailed analysis can still reach work/memory limits. Actual
Copilot model accuracy and a real Windows SafeRTOS/Wind River workspace remain
unverified; native Windows/macOS/Linux CI is checked separately.
