# Dynsight 0.1.96

Fixes repeated Rebuild index prompts after restarting with a saved build configuration. Dynsight now restores that configuration before opening its analysis cache, so an unrelated older basic cache cannot block a compatible selected-build cache.

Startup retains source candidates and restores the selected cache's inherited analysis policy, including an explicitly empty legacy scope. Build-specific relationships are reconstructed from cached source analysis without reparsing unchanged files or replacing a valid source-cache generation.

Rebuilds and configuration changes wait for initialization. Incompatible or damaged selected caches remain protected until you explicitly choose Rebuild index; missing selected caches are created under the selected configuration. Analysis cache compatibility stays at 19, and real version or settings mismatches still require rebuilding.

Regression coverage includes restart, stale and damaged caches, build metadata refresh, policy restoration, configuration changes and disposal during startup. Downloads for Windows, macOS and WSL contain the same JavaScript/WASM extension.
