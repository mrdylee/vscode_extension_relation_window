# Dynsight 0.1.64 — WSL local-first Copilot candidates

Dynsight now gives Copilot a shortlist of callback candidates already found by
local registration and data-flow analysis, together with their source evidence.
Copilot reviews these candidates instead of starting with a broad list of nearby
function references.

- Reuse existing object/field, parameter-position and getter analysis. Different
  objects are not joined merely because their callback field names match.
- Bound the local review context to eight candidates, ten source snippets and
  8,000 source characters. Include bounded getter/caller context when available.
- Fall back to the existing broader source search when no usable local candidate
  is available. Shortlists remain incomplete and show **Context limited**.
- In a synthetic 40-field callback table, the context JSON fell from 9,084 to
  1,081 bytes and retained the correct local candidate previously lost to the
  32-target limit. This is not a measurement of real Copilot response latency.

The prompt cache format has changed. After updating, save modified C/H files and
run **Dynsight: Analyze Callbacks with Copilot** to refresh missing AI results.
Startup and normal navigation still make no new AI requests. Local candidates
remain available even when the model returns no candidate.

Install `dynsight-0.1.64-wsl.vsix` in the WSL extension host and reload VS Code.
Only the WSL package is distributed; the common and legacy filenames contain the
same bytes for existing automatic updaters. No Windows/macOS download copies are
provided. Validation uses Ubuntu/Linux; live WSL installation is not verified here.
