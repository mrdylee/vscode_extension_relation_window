# Dynsight 0.1.44

Settings, extension identity and publisher now use the new name too:
**Dynsight — C Code Explorer**, publisher **dylee**, ID **`dylee.dynsight`**.
Settings and commands use `dynsight.*`; downloads use `dynsight-0.1.44`.

## One-time upgrade from v0.1.43 or earlier

Install the Windows, macOS or WSL VSIX and open a C file. Choose
**Remove previous extension and reload** when prompted. If you dismiss it,
uninstall the previous extension (C Relation Explorer / James Black) in Extensions
and run **Developer: Reload Window**. New analysis waits while the old extension
is active. In WSL, perform this in the WSL extension host. If the previous
extension is disabled, remove that entry manually.

Existing explicit settings migrate at user/workspace/folder scopes when the new
extension activates. Existing `dynsight.*` values win; migrated `cRelation.*` keys
are removed. Other projects migrate when opened. Reload after adding a folder
with legacy settings. Old custom keybindings remain compatible. Panel placement
may need to be restored because view IDs changed.

The legacy-named `c-relation-explorer-0.1.44.vsix` is an identical compatibility
download for old update clients. All five VSIX assets contain the same universal
package. Use the `dynsight-*` downloads for manual installation.

Analysis behavior and memory limits are unchanged. This release completes the
name migration; it does not claim a new fix for partial-index memory warnings.
