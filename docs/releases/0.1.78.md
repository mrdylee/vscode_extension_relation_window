# Dynsight 0.1.78 — Windows batch and Make analysis repairs

Install the Windows, macOS or WSL VSIX in the matching VS Code environment and
reload. All platform filenames contain the same universal extension.

- Follow direct batch transfers and `call`, handle Windows environment/file-name
  case and PATH assignments, and model literal generated `.cfg`/`.mk` settings in
  memory. Project scripts, compilers and Make are never executed.
- Resolve nested pure Make functions, substitution references, lazy define
  blocks and target-specific/inherited module flags before contextual analysis.
- Apply ordered explicit `-D`, `-U` and `-I` for GCC and Diab `dcc`. Show located
  reasons for unsupported options, pre-build generators and missing artifacts.
- Keep established compiler invocations when later postprocessing is unsupported.
  The preview now distinguishes compile inclusion from partial final link coverage.

After updating, select the existing build entry and use **Dynsight: Refresh Build
Configuration**. Cache compatibility is now 14; rebuild an incompatible saved
index. Existing callback/work/memory limits and analysis scope are unchanged.

Unknown generators, arbitrary shell/Make constructs, additional Diab target
options, compiler defaults and final link membership can still leave partial
results. This patch has synthetic GCC/Diab regression coverage; the photographed
private firmware has not been run here and is not claimed fully resolved.
