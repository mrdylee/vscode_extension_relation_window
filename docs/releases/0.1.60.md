# Dynsight 0.1.60 — WSL

## Callback mutation budgets

With **Analyze Callbacks** enabled, integer status fields read only by logging
could consume the 256-slot callback mutation summary. Scalar effects now follow
callback dependencies through selectors, conditions, assignments, aliases,
helper parameters and returns. Proven unrelated scalar writes and opaque
scalar regions no longer consume callback effect/region entries. Unknown types,
unions and callback-related storage remain conservative.

Fields in unrelated structure types or local structure declarations no longer
share scalar dependencies solely because they have the same member names.
Compatible declarations across translation units still retain dependencies.

A limited indexed helper no longer invalidates every pointer argument. Only
its actual changes and omitted storage effects propagate uncertainty, including
no-argument global writes and call-site effect expansion. Unused callback
objects remain complete without extra unresolved edges.

All existing budgets remain. More than 256 relevant selector/callback effects,
truncated reachable-object traversal and exhausted omission tracking can still
produce warnings and uncertainty. This release does not hide those warnings.

## Verification and limits

Synthetic regressions, the budget audit, Worker transfer, browser UI and native
VS Code Extension Host checks cover the repaired behavior. The complete FreeRTOS
corpus still reaches analysis limits; this is not a claim that every large
project finishes without warnings. The user's complete WSL source project is
not available here and has not been validated.

Install `dynsight-0.1.60-wsl.vsix` in VS Code's WSL extension host, reload the
window, and rebuild the index with **Analyze Callbacks** enabled. Copilot is not
required. Common and legacy filenames remain available for existing updaters.
