# Release review: 0.1.64

## Scope and existing architecture

Reviewed the local-candidate context builder, prompt/cache changes, regression
tests, documentation, version metadata and the existing WSL release workflow.

- Symbol collection: `src/analyzer.ts`; ordered parameters and intermediate
  assignment/call facts: `src/flow-parser.ts`.
- Existing registration, object, parameter and getter propagation:
  `src/explicit-callbacks.ts`, `src/pointer-targets.ts`, `src/partial-callbacks.ts`.
- Relation trees and cursor lookup: `src/relations.ts` (`graph`, `callbackAt`);
  Context/source navigation: `src/view.ts`.
- Reuse those results rather than adding a second callback graph or field-name
  join. New context construction does not change local inference or UI navigation.

## Findings and resolutions

- A broad context could fill the first 32 target slots with unrelated callback
  table entries and omit a target already found by local analysis. Prefer
  per-callsite registered/incomplete inferred target IDs and their source evidence.
- Keep candidates from different object/type bindings separate. Broader bridge
  source lookup enriches context only and never invents target IDs.
- Local inference evidence may contain only a function address. Add bounded
  getter/caller source context; cross-file parameter-slot/getter regression passes.
- Cap local review at eight candidates, ten snippets and 8,000 source characters.
  Preserve incomplete/limited scope and unresolved calls. Responses outside the
  offered targets/evidence fail validation; model rejection does not delete local
  registration candidates.
- Bump the AI prompt-cache version. Changed registrations invalidate results;
  cache restoration continues to make no new requests. Retain existing saved-source,
  cancellation, model selection and five-new-request limits.

## Validation evidence

- Local `npm run typecheck`, `npm run build` and all 413 `npm test` tests passed.
- Six added regressions cover candidate priority, different objects with the same
  field name, cross-file getter/parameter evidence, prompt/cache behavior, rejection
  of outside candidates and broader-search fallback.
- Identical synthetic 40-field input: the old context offered 32 targets and
  omitted `target_39`; the new context offers `target_39` alone. Context JSON is
  9,084 versus 1,081 bytes (88% reduction); source snippets are 20 versus two.
  These measurements exclude the instruction text and do not measure model latency.
- Publication is gated by the existing Ubuntu CI test and release workflow.
  Live WSL remote installation and real-user-project model latency remain unverified.

No unresolved blocking findings were identified in the reviewed change.
