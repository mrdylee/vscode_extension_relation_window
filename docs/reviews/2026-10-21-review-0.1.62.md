# review-work — callback limit evidence on an offline WSL host, 0.1.62

Base: 26bc0fb (0.1.61). The user asked what 256 means and approved proceeding
with measurement before claiming a root-cause fix. The affected 196-file corpus
is on a security-isolated PC and cannot be accessed remotely.

## Scope and review

- Retain Analyze Callbacks and every existing analysis budget/uncertainty rule.
  This is a diagnostic release, not a claim that Partial index is resolved.
- Record the first overflow operation, retained count, omitted location and up
  to eight retained examples per existing bounded diagnostic. Cover direct
  writes, branch joins, instantiated call effects, function effects, ordered
  regions, reachable-region traversal and exported function regions.
- Accumulate per-function propagation visits, cache hits, expression evaluations
  and elapsed wall time. Attach the eight highest evaluation counts once to the
  first detailed notice. Cached visits are not counted as body evaluations.
- Build storage labels only when a new detail is retained, preserving the
  existing 64-record bound. Counter storage scales with analyzed functions;
  exported rankings and examples are bounded. No source text is duplicated.
- Local notices/cache may include source names. The existing allowlist in
  Report issue excludes the new fields; a secret-marker regression covers
  samples, function names and locations. No network behavior is added.
- Local self-review: inspect the full diff, declaration initialization order,
  overflow collection boundaries, callback-result semantics, cache-hit accounting,
  diagnostic serialization and UI rendering. No review subagents were requested.

## Red / green and measurements

Three new regressions failed on missing diagnostic fields before production
changes. They now identify the exact 257th field, distinguish ordered regions,
and render both storage evidence and accumulated costs. A further assertion
checks that a cached function has one real analysis visit and nonzero cache hits.

An isolated archive of HEAD 26bc0fb was compared with the changed engine on a
synthetic 257-field writer plus 300 functions making 20 callback calls each.
Both ran Analyze Callbacks ON; two warmups and five measured trials alternated
order. References, issues and function-argument outputs were byte-identical on
all trials. Baseline derive times were 84/83/84/88/86 ms; changed times were
85/84/84/87/86 ms (medians 84/85 ms). This small local measurement does not predict
security-PC performance or identify its bottleneck. The recorded overflow was
`write`, retained=256, first omitted=`data.cb256`; `heavy` ran twice with 1542
expression evaluations and subsequent functions reused cached observations.
