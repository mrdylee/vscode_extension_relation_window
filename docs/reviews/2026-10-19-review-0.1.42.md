# v0.1.42 review — unchanged-source reuse

Scope: fix unnecessary analysis on unchanged editor closure/watcher notifications.
Review base: `874797f62b71964023d2fbe15db0302a6fb2ee35`.

## Implementation and review

- Compare the current source against the accepted index only after disk/buffer
  reading and epoch/version/Worker-error checks. Reuse requires an accepted raw
  Worker version; no new source copies or hash cache are retained.
- Invalidate the accepted raw version before dispatching a changed source. A
  superseded response may already have changed the Worker's raw input. Comparing
  host text alone would incorrectly skip restoration when an edit is reverted.
- Keep the close handler: discarded unsaved edits still need to restore disk
  contents. Scope/configuration rebuilds already clear raw versions and indexes;
  removal and failure paths remain invalidating. No memory guard changes.
- Reviewed all analysis entry points, asynchronous result guards, deletion,
  rebuilding, failure recovery and callback-result retention. No outstanding
  release-blocking findings in this change.

## Review findings addressed

The initial revert test could pass with stale Worker state hidden behind a correct
host index. It now forces an unrelated file update after the revert. A local
mutation removing raw-version invalidation fails with `Partial index: call
analysis failed`, while the actual implementation passes. The mutation was only
in an ignored probe, never the production tree.

The native test initially assumed closing a tab immediately closes its document.
VS Code retains documents in a cache. The corrected test opens/closes 90 source
headers, requires real document-close events, and checks that the index revision
is unchanged after pending work settles.
