# v0.1.49 review — callback call-site navigation

Base: `f724ac2` (v0.1.48 publication audit).

## Scope and design

The user clarified that callback search means tracing the targets of `cb()` or
`ops->callback()`. Reuse indexed pointer inference rather than running another
analysis or adding name search. Candidates remain explicit, even for one target.
See `docs/plans/2026-10-20-callback-navigation.md`.

The existing ordinary `resolveAt` deliberately skips inferred call records and
continues to resolve variables/members. The new `callbackAt` lookup is separate,
scoped to one file and one call location, and returns possible functions plus
incomplete/unknown status. Editor and Context tracking expose these in a compact
selector; choosing a candidate opens its normal graph and permits pinning.

## Review corrections

- Callee-token selection must not consume object/index navigation. Reproduced
  with `(*x.cb)()` and `table[i]()` and restricted lookup to the callee token.
- Basic-only analysis must report unknown rather than silently imply a complete
  target set. Candidate data refreshes when derived results become available.
- Choosing stale candidates during index replacement must not lose the selected
  call site. Native failure reproduced; current index is rechecked before choose.
- In `factory()()`, the inferred outer call can share the identifier's location.
  Inspection showed the ordinary factory reference becomes `kind: reference`;
  checking only `kind: call` was insufficient. Preserve ordinary function
  resolution at that token. No pointer-inference algorithm change.
- Pin is disabled until a resolved root has been chosen. Existing pin, source
  tracking pause/resume, scope, traversal modes and argument settings remain.
