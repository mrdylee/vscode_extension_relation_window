# Callback diagnostics review — 0.1.52

Local review against `checkpoint/pre-callback-limit-diagnostics-20261020`
(`1c68775`), pushed before edits.

Findings addressed:

- Generic callback warnings previously used the first file with a call. Capture
  the observed location/symbol in the analyzer and format it from that location.
  Setup/project-wide diagnostics use a project label with no blamed file.
- A large global initializer built a function effect summary that was discarded,
  yet its cap marked the entire inference incomplete. A failing 300-element
  fixture reproduced this. Skip only the synthetic global context's effects;
  keep heap writes, real function effects and callback targets.
- A time/memory check location is not exclusive-cost attribution. Label it
  **Project budget observed at** and document per-visit scope counters.
- Bound details to 64 distinct reason/symbol/stage records. Preserve generic
  incomplete-result notices, including a project fallback for omitted details.
  Macro limits and located callback limits precede ordinary syntax notices.
- Explicitly allowlist report kinds/stages and numeric counters. Never serialize
  diagnostic messages, function names or paths into the generated summary.
- Option changes and file deletion must remove stale diagnostics. Worker and
  native tests cover those transitions.

No safety limits increased; no new project-wide analysis on cursor selection,
argument-ordinal special case, unbounded history or broad inference refactor.

Validation includes 244 unit tests, 25 Worker/workspace tests, 4 memory tests,
index performance checks, browser UI and isolated native VS Code checks.
Regression tests cover real function mutations, original macro source locations,
pre-inference memory pressure, deterministic project timeout, bounded records,
warning ordering and report privacy. Package/platform publication checks are
recorded separately after completion.

A local comparison with 4,000 scalar initializer elements and one indirect call
preserved the same target and removed the false mutation warning. Six runs per
version gave median inference times 3.139 ms before and 2.966 ms after, excluding
parsing. This small synthetic comparison does not establish private WSL speedup.
The user's original project and its 10-second callback limit remain unverified.
