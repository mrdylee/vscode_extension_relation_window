# Smart Analysis: one AI setting and guided selection

The user's correction is to expose one AI setting and select an installed extension followed immediately by its model from lists. This supersedes the separate Provider/Copilot Model settings and default-only Claude/Codex UI in 0.1.87. The earlier deployment request continues to cover this correction; the release version is 0.1.88.

## Result

- Only **Smart Analysis: AI** is visible. Checking it opens **1/2: extension**, then **2/2: model**, even when only one extension is installed. The same row links to the complete flow for changing the selection. Legacy provider/model schemas and command aliases remain compatible but are hidden; the new flow never writes those settings.
- Models use display names, with no text/ID prompt. Copilot uses the VS Code Language Model API. Codex initializes its selected bundled app server and pages through `model/list`; Claude Code sends only the initialize control request and reads the returned model metadata. No inference/source prompt is sent during discovery. Claude/Codex offer an explicit default-model item if additional metadata is unavailable.
- The complete provider/model pair is saved once in workspace state after both picks. Cancel preserves the last completed pair and turns a newly enabled checkbox off in its original User or Workspace scope. Turning AI off aborts pending discovery and selection. Diagnostics and progress show the chosen model name.
- Setup pauses and cancels the previous analysis before switching. Only the selected provider/model receives source requests, cache identity includes the model, and failures never choose another provider. Existing source scopes, manual targets, evidence validation and sequential scheduling remain in place. Analysis cache compatibility remains 16.
