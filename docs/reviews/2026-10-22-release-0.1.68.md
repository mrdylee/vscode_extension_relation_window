# Release review: 0.1.68

## Problem and correction

0.1.67 shipped UI/scope/cache review fixes but omitted the type and memory-model
findings from analysis.md. This release fixes those analysis paths.

1. Tree-sitter primitive typedef declarators are now collected. Visible aliases
   retain priority over standard integer-name fallbacks. Scalar information and
   declaration identity survive indexing/dereferencing, so byte buffers and
   unused numeric fields are excluded from callback summaries while real
   selectors continue to propagate their effects. Arrays retain type information
   during initialization and aggregate copies too.
2. External memcpy/memmove/memset invalidate destination bytes without following
   destination pointer fields or invalidating read-only source objects. Shallow
   effects survive wrapper summaries and branch joins. Zero-size operations
   preserve storage; returns alias the destination. Array ranges are conservatively
   widened. Unknown copied callback bytes remain unknown. User function bodies
   and same-named function-pointer variables retain ordinary call analysis.
3. sizeof/alignof previously produced a literal zero to suppress operand effects.
   That misrepresented actual byte counts. They now produce an unknown value
   without evaluating the operand.
4. Function caches track per-object/array shape and matching heap invalidations,
   replacing total heap size and global region revision dependencies. A regression
   fixture drops unrelated callback reader evaluations from two to one while
   still catching late wildcard writes, concrete elements and matching regions.

Analysis compatibility advances to 2 to invalidate old parsed/inferred results.
The 256-region/mutation, 12-pass and 10-second safety limits are unchanged.

## Evidence before publication

- All 486 unit tests passed, including 36 additional regression cases.
- The original synthetic analysis.md checks now have no unwanted limit notices
  for 257 uint32_t fields, visible/indexed typedefs, 257 byte writes and repeated
  byte copies. A source callback remains resolved after memcpy.
- Node 22 Worker/cache/workspace integration: all 46 tests passed. A codec-style
  fixture verifies Index ready, preserved source callbacks and no false limits.
- Node 22 memory/cache collection: all four tests passed. Index performance
  validation passed, including 12500 files / 125010 references.
- TypeScript checking and production build passed.
- Diagnostic fixtures formerly relying on the bug (unread int array writes)
  now use real callback slots, retaining coverage of genuine mutation limits,
  record bounds, Worker transfer and source/macro locations.

Actual firmware sources/settings from the analysis.md author's 196-file project
are unavailable here. No claim is made that every real-project timeout or limit
has disappeared. ABI byte-copy values are not inferred into certain callback
targets. Live WSL remote installation is unverified.
