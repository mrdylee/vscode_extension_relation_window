# Release review: 0.1.63

## Scope

Reviewed `webview/main.ts`, `webview/styles.css`, version metadata, changelog,
release notes and the existing WSL-only release workflow before publication.
The footer change does not alter indexing, callback inference or AI requests.

## Findings and resolution

- Copilot previously forced a new row with `flex-basis: 100%`, and the footer
  wrapped its children. Remove those constraints and order the status fields as
  index, Copilot and Analysis notices before shortcuts and Diagnostics.
- Long progress text could squeeze the short index status unnecessarily. Keep
  the index from shrinking, cap long index messages at 30% and allow progress
  and shortcut text to truncate. The complete index text remains in its tooltip.
- Expanded notices must not increase the footer height. Position the scrollable
  notice contents above it, preserving the native details/summary toggle.
- The release workflow already builds on Ubuntu and publishes only WSL packages
  with identical automatic-update filename aliases. No platform matrix change
  is needed and no Windows/macOS copies will be produced.

## Validation evidence

- `npm run typecheck` and `npm run build` passed after the footer change.
- The existing browser UI suite passed with the installed Chromium executable.
- Additional temporary browser checks passed at 1450, 900 and 520px widths for
  Copilot off, ready, pending and paused states: left-to-right ordering, aligned
  status centers, visible status areas, no horizontal page overflow, and notices
  opening above a footer whose height stays unchanged.
- Release publication remains gated by the existing GitHub Actions unit, memory,
  performance, worker, Extension Host and large-workspace checks.
- Live WSL remote connectivity and remote installation are not verified here.

No unresolved blocking findings were identified in the reviewed change.
