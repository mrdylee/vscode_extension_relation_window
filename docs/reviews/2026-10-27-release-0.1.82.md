# Propagation review and release: 0.1.82

## Scope and review finding

The reported symptom is propagation limits or slow analysis. Review covers the
pending conditional-expression fix, its work/memory impact, cache invalidation,
GCC/Diab build refresh and the delivered extension.

The incoming fix correctly preserved conditional writes, but constructed callback
branches for every logical expression. A new regression with 3,000 ordinary
8-operand logical conditions exhausted the default function-work budget before
the following callback call: the expected `foo` target was absent. This test
failed before the review correction. Detect actual side effects before creating
a logical branch; preserve always-evaluated left effects and conditional right
effects. Pure wrapped conditionals also avoid unnecessary side-effect records.

Keep nested ternary writes conditional, preserve helper/caller alternatives and
retain unknown logical result values rather than treating them as function
addresses. Advance analysis cache compatibility from 15 to 16 so saved raw flow
facts and derived results rebuild. No propagation limit was raised or disabled.

## Remaining limit and latency evidence

The public single-port FreeRTOS 33-file corpus still reached the 20-second
measurement cancellation in the earlier audit. CPU time concentrated in opaque
region invalidation and containment checks. An early queue-deduplication
experiment reduced queue duplication without establishing consistent speedup;
it is not included. This input lacks the user's actual firmware build settings
and emits unsupported-syntax/macro warnings. It cannot validate the user's
private firmware limit warning or prove overall latency resolved.

Raw local audit evidence is in `artifacts/propagation-self-audit/`; release
validation and package evidence is in `artifacts/release-0.1.82/`.
