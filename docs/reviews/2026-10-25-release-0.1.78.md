# Release review: 0.1.78

## Implemented and reviewed

Based on clean main `edc1eaa`; design/plan committed as `e19a2bd` on
`fix/windows-build-context`. User explicitly requested fixes, GCC parity,
implementation tests and deployment. No project build script is executed.

- Windows cmd environment/file-name case, PATH, direct batch transfer versus
  returning `call`, and bounded read-only cfg/mk overlays.
- Balanced nested pure Make expansion, lazy definitions, substitution/list/path
  functions, target-specific immediate/recursive/inherited flags, exact-over-pattern
  precedence, automatic variables and order-only prerequisite traversal.
- Established compile commands survive unsupported postprocessing. Unknown
  pre-build effects remain conservative; sibling target failures do not leak.
- Unknown header generation makes an old disk header unavailable to contextual
  preprocessing rather than selecting stale branches. Profile diagnostics retain
  artifact and source-expression provenance.
- GCC/Diab common ordered explicit D/U/I options, located preview reasons and
  compile inclusion versus final link coverage. Cache semantic version 14.
- Existing extraction, callback, alternative, work and memory limits preserved.

## Limits

No actual Windows firmware, installed toolchain or live Copilot response was run.
GCC/Diab option tests use static invocations and contextual analysis, not native
compiler execution. Arbitrary pre-build executables, unmodeled Make/shell
semantics, Diab-specific target/options/defaults and final link membership remain
uncertain. Unsupported work is not silently declared complete. This release is
not a claim that the private corpus's callback limits or every unknown are fixed.

Public release/CI/download verification is recorded after publication; existing
published or failed tags will not be moved.
