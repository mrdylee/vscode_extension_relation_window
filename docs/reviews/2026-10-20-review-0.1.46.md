# v0.1.46 review — persistent diagnostic issue reports

Base: `b844b1dc233e7babfda27b382a9dbc9c3eac9c18`.

## Scope and local review

- Improve existing Report issue rather than adding a separate UI. Capture small
  explicit metadata records to workspace storage, retaining three uniquely named
  sessions with two 256 KiB segments each. Async writes are serialized with a
  64-record queue; oversize records and older queued records can be dropped.
- Record periodic last-known Worker samples, shared host heap/RSS, rebuild/source
  activity metadata and navigation action types. No source identifiers, code,
  configuration values or raw errors in the journal. RSS includes the shared host
  and its Workers; it is not a Dynsight-exclusive allocation measurement.
- Read only known host log filenames in current/preceding log sessions. Tail reads
  are bounded, lifecycle/OOM lines selected, known roots/URLs redacted, unsupported
  or missing sources labeled. Previous session association is explicitly uncertain.
- Preserve current draft, copy/manual-browser behavior and add Save report for the
  reviewed content. Cancel/error never uploads or loses the draft. The collector
  makes no analysis requests and does not rebuild the index.
- Review fixes, each reproduced by a failing regression test before correction:
  explicit field projection prevents unexpected metadata from entering the journal;
  redact URLs before filesystem roots to avoid exposing URL query tails; report
  collection reads saved records without waiting for pending journal writes.
- Reviewed retention, rollover, write failure, Markdown fence handling, read limits,
  diagnostics event disposal and unchanged graph/index behavior. No blocking local
  findings remain. No analyzer/memory-budget changes or crash fix claimed.

## Validation

- Typecheck and 214 unit tests passed, including six filesystem/history cases and
  nine reporting-adapter cases. Tests cover restart retention, rotation, queue
  bounds, failed storage, current/prior host logs, redaction, missing/unsupported
  layout, bounded tails, delayed writes, save/cancel/failure and manual sharing.
- 19 Worker/workspace tests and the browser UI suite passed.
- Native VS Code integration passed from source and the final extracted v0.1.46
  VSIX. Reporting works with Worker requests disabled and preserves graph and
  clipboard; the actual local host log layout and saved journal were collected.
- Package ZIP integrity checked. Cross-platform CI/public download verification
  follows separately in the publication audit.

## Limits

Actual WSL host-crash reproduction is not available locally. WSL paths are covered
by fixtures; native log discovery is verified on macOS. Internal VS Code log layout
can change. Host excerpts may retain private metadata and require human review.
A dead/frozen host cannot record; pending records may be lost. No pre-installation
Dynsight history is reconstructed. Existing host logs are best-effort evidence.
