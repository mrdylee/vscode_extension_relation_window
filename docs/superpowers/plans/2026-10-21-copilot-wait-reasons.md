# Copilot 대기 원인 표시와 재개 검증

사진의 v0.1.56은 `waiting for saved index · 0/0`이다. 실제 대기 원인이나 이전 10분 지연은 아직 재현되지 않았다. 현재 모든 대기 이유를 합쳐 보여주는 문제는 코드에서 확인했다.

## 설계

자동 무한 재시도, 미저장 소스 전송 허용 대신 현재 준비 조건을 유지하고 차단 이유를 표시한다. 미저장 소스, 최초 인덱싱, 파일 갱신, 관계 갱신, 캐시 오류, Worker 오류, 관계 분석 실패를 구분한다. 대기 상태에서는 초기화된 0/0을 완료/실패 통계처럼 표시하지 않는다. 경로·소스·원시 오류는 새 진단 필드에 넣지 않는다. 일반 Partial index 한도 경고는 실행 차단 조건으로 추가하지 않는다.

## 구현 및 검증

1. 서비스 테스트에 미저장 대기 이유와 저장/settled 후 재개, stable partial 결과 허용을 추가한다. 이유 필드 테스트 실패를 먼저 확인한다.
2. WorkspaceIndex의 현재 준비 조건에서 이유 코드를 읽는 getter와 진단 타입을 추가한다. 서비스의 run/schedule/clear에서 이유를 갱신하고 실행 시 지운다. 새 요청의 권한·한도·캐시 정책은 그대로 둔다.
3. 공통 진단 메시지를 footer와 Diagnostics에 표시한다. issue report에는 허용된 이유 코드만 포함한다. Workspace getter와 메시지/신고 테스트를 추가한다.
4. 관련 단위 테스트, 타입 검사, Worker/Workspace 테스트, UI 확인을 수행한다. 기존 미커밋 0.1.57 변경은 보존하며 이번 작업에서 버전 변경·게시하지 않는다.

성공 기준: 사용자가 대기 원인과 조치를 읽을 수 있고, 저장 후 최신 결과만 재개하며, 미저장/차단 상태에서는 AI 요청을 보내지 않는다. 사용자의 WSL 실제 중단 해결이나 모델 속도 개선은 별도 재현 전까지 주장하지 않는다.
